# ProbKnow Space and templates

The nanopublications that set ProbKnow up on the nanopublication network: a
**Space** (`https://w3id.org/spaces/probknow`) and the **templates**, governed by
that space, from which every kind of ProbKnow nanopublication is created. With
these published, the pipeline's nanopubs can link to their templates
(`nt:wasCreatedFromTemplate` and friends), Nanodash renders them with their
forms, and any member of the space can publish the next version of a template
without needing the key that signed the previous one.

| File | What it is |
|---|---|
| `src/01-space-probknow.trig` | The ProbKnow Space (a `gen:Group`), admins Tobias Kuhn and Joel Dietz. Created from the Space template. |
| `src/02-template-provenance-probknow-extraction.trig` | Provenance template: the assertion is attributed to an agent (the ProbKnow system agent or the creator) and derived from a paper (DOI, title, year). |
| `src/03-template-pubinfo-probknow-domain.trig` | Pubinfo template: the `pk:domain` of a nanopub as a `pkr:domain/<slug>` IRI. |
| `src/04-template-probknow-claim.trig` | Assertion template: a `pk:Claim` with context, evidence links, assessments, source paper and weight of evidence. |
| `src/05-template-probknow-evidence-item.trig` | Assertion template: a `pk:EvidenceItem` with statistical test, p-value, Vovk–Sellke bound and weight. |
| `src/06-template-probknow-bayesian-assessment.trig` | Assertion template: a `pk:BayesianAssessment` of a claim with Bayes factor, decibans and calibration method. |
| `src/07-template-probknow-llm-assessment.trig` | Assertion template: a `pk:LLMClaimAssessment` of a hypothesis by a language model. |
| `src/08-template-probknow-testable-hypothesis.trig` | Assertion template: a `pk:TestableHypothesis` with proposed test, prior and resolvability. |
| `src/09…15-maintained-*.trig` | One per template: declares the template's *kind* a maintained resource of the Space, which is what makes `gen:governedBy` take effect. For the five assertion templates this uses "Listing a template as a maintained resource", which in the same nanopub assigns the *Maintained template preset* (the standard views of a template page); the provenance and pubinfo kinds use the generic maintained-resource template. Generated by `sign.sh` from the signed templates, since the kinds are minted by them. |
| `src/16-space-role-helper.trig`, `src/17-space-helper-probknow-bot.trig` | The ecosystem's Helper role (member tier) attached to the Space, and the pipeline bot granted it, so the bot's nanopubs count as the space's and it can publish governed template versions. |

`generate.py` writes `src/01…08` from a compact spec (edit the spec, not the
TriG). `sign.sh` fills the timestamps, signs everything in dependency order with
the local nanopub profile key (`~/.nanopub/profile.yaml`), derives and signs the
maintained-resource declarations, and runs `check` over the result:

```bash
python3 nanopubs/generate.py
bash nanopubs/sign.sh            # → nanopubs/signed/
```

Publishing is a separate, deliberate step, in the printed order (Space first,
then templates, then the maintained-resource declarations), with the
nanopub-java CLI:

```bash
for f in nanopubs/signed/*.trig; do java -jar nanopub-<version>-jar-with-dependencies.jar publish "$f"; done
```

Design notes:

- Templates follow the current meta-templates of the ecosystem: assertion
  templates have **embedded identity** (`sub:template`, referenced as
  `<nanopub>/template`) with a stable **kind** (`dct:isVersionOf`, introduced by
  the nanopub) and `gen:governedBy` the ProbKnow space. Provenance and pubinfo
  templates are still defined through legacy-identity meta-templates, so they use
  the documented half-way form: the assertion graph is the template node and
  carries the kind and governance triples.
- Introduced resources are minted under the `pkr:` namespace from the
  nanopublication's **artifact code**: the templates name them
  `pkr:<kind>/~~ARTIFACTCODE~~`, which Nanodash expands at publish time
  (`pkr:claim/RA…`), and which it matches against any `pkr:<kind>/<id>` when a
  form is filled from an existing nanopub. The pipeline mints the same form when
  no id is given and otherwise uses its own ids under the same namespace, so both
  conform to the templates. References to other ProbKnow resources (evidence
  items, assessments, claims) are guided choices searched on the network by
  class.
- Naming a maintained resource: the declaring nanopub's pubinfo `rdfs:label` must
  be exactly the resource's own name, the same string as the resource's
  `rdfs:label` in the assertion. Nanodash takes a maintained resource's display
  name from the declaring nanopub's label (a query-level fix, nanodash PR #764,
  is pending), so a sentence there becomes the resource's name. The first seven
  declarations (`signed/09…15`) had such sentences and were superseded the same
  day by label-only new versions (`signed/*.v2.trig`, assertions byte-identical);
  `sign.sh` now writes the plain name.
- Versions: a template with a `change_note` in `generate.py` is generated as a
  new version of the published one recorded in `published.json`, superseding it
  and keeping its kind IRI. Sign only those files
  (`bash nanopubs/sign.sh nanopubs/signed nanopubs/src/04-*.trig …`); the
  maintained-kind declarations stay as they are. After publishing, update
  `published.json`.
- The templates were checked with the nanopub skill's
  `check-template-conformance.py` (all statements matched against the
  meta-template) and `check-nanopub-conformance.py` (Space and maintained-resource
  declarations), and every signed file passes nanopub-java `check`.
- `pipeline/probknow-builders.ts` references the signed templates' IRIs in every
  nanopub's pubinfo (its `TEMPLATES` table). `sign.sh` writes the IRIs to
  `signed/template-iris.json` and runs `update-builders.py`, which pastes them
  into that table, so the pipeline and the signed templates never drift apart.
  Pipeline output was checked against the templates with
  `check-nanopub-conformance.py` (cache pre-seeded with the unpublished
  templates): claim, evidence item, Bayesian assessment, LLM assessment and
  testable hypothesis nanopubs match their templates fully.
